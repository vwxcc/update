# AI CH: установка с нуля и автообновления для ZimaOS

Репозиторий устанавливает **AI CH** из `vwxcc/deepseekw` на ZimaOS, а затем автоматически проверяет новые коммиты ветки `main` каждые 3 минуты.

## Что делает установщик

- Работает на самом хосте ZimaOS от root (используй `sudo`).
- Для приватного `vwxcc/deepseekw` использует отдельный GitHub fine-grained token с правом `Contents: Read-only`; token вводится скрытым вводом и проверяется до установки.
- Если контейнера ещё нет, скачивает конкретный коммит `vwxcc/deepseekw/main` через авторизованный GitHub API, проверяет обязательные файлы и синтаксис Python.
- Использует готовый базовый образ `python:3.12-slim`: **Dockerfile/build/buildx не нужны**.
- Создаёт контейнер (по умолчанию `ai-ch`) с портом хоста `3050` → `8000`, постоянными каталогами `/DATA/AppData/ai-ch/data` и `/DATA/AppData/ai-ch/uploads`, автоперезапуском `unless-stopped`.
- При первой установке спрашивает email и пароль администратора и генерирует случайный `SESSION_SECRET`. Файл `/DATA/AppData/ai-ch/.env` имеет права `600`; повторный запуск его не перезаписывает.
- Устанавливает Python-зависимости при первом старте контейнера, затем запускает `uvicorn app.main:app`.
- Ждёт ответ `/api/health` перед включением автообновлений. Если проверка не проходит, оставляет контейнер и данные для диагностики, а не удаляет их.
- Устанавливает systemd service/timer. Обновлятор использует `GITHUB_TOKEN` из `/etc/ai-ch-updater.env`, проверяет SHA приватного репозитория, скачивает релиз в staging через GitHub API (без передачи token в URL), сохраняет резервную копию кода, устанавливает изменившиеся зависимости изолированно, применяет код, проверяет health-check и пытается откатиться при ошибке.
- При повторном запуске не пересоздаёт существующий контейнер и не меняет существующий `.env`. Если контейнер существует, проверяет, что он запущен и содержит структуру AI CH.

При установке/обновлении самого updater сценарий также разворачивает отдельный контейнер `ai-ch-sandbox` из текущего коммита `vwxcc/deepseekw`. Runner подключён только к внутренней Docker-сети `ai-ch-sandbox-internal`, без публикации портов на хост; root FS только для чтения, ресурсы ограничены, bearer-ключ хранится в `/DATA/AppData/ai-ch/data/.sandbox_api_key` с правами 600. Код пользователя выполняется под отдельным UID, а сетевые системные вызовы блокируются seccomp. Зависимости ставятся в отдельный временный подготовительный контейнер; рабочий runner не подключён к интернет-сети. Обновления runner также происходят автоматически вместе с обновлением репозитория.

При повторном запуске установщика существующий token читается из `/etc/ai-ch-updater.env`. Если файла или token в нём ещё нет, установщик попросит ввести token заново. Для обновления уже установленного обновлятора скачай актуальный `install.sh` и запусти его на хосте ZimaOS; укажи то же имя контейнера и порт. Само приложение, `.env`, база данных и пользовательские загрузки при такой перенастройке не пересоздаются.

## Установка

Выполни на терминале **хоста ZimaOS**, не внутри контейнера:

```sh
curl -fsSL https://raw.githubusercontent.com/vwxcc/update/main/install.sh -o /tmp/ai-ch-updater-install.sh
sudo sh /tmp/ai-ch-updater-install.sh
```

Если терминал уже запущен от root, можно убрать `sudo`.

Установщик спросит:
- имя контейнера (по умолчанию `ai-ch`);
- внешний порт (по умолчанию `3050`);
- GitHub fine-grained token для приватного репозитория;
- email администратора при первой установке;
- пароль администратора при первой установке (не менее 8 символов; для безопасной записи в Docker env-файл разрешены латинские буквы, цифры и `._@%+-`).

**Какой token создавать:** открой [создание fine-grained token GitHub](https://github.com/settings/personal-access-tokens/new), выбери только репозиторий `vwxcc/deepseekw` и разрешение **Contents: Read-only**. Не выдавай `Contents: Read and write`, доступ к другим репозиториям или административные права. Обязательное разрешение `Metadata: Read-only` GitHub добавляет автоматически. Вставляй token только в скрытый запрос установщика — не присылай его в чат и не добавляй в Git.

После успешной установки сайт будет доступен по адресу `http://IP-адрес-ZimaOS:3050/`. Открой его и войди с данными администратора, заданными при установке. API-ключ и модель можно настроить в админ-панели AI CH. Файл `.env` не публикуй и не отправляй в чаты.

## Постоянные данные и файлы

- Настройки и секреты: `/DATA/AppData/ai-ch/.env`
- SQLite и данные приложения: `/DATA/AppData/ai-ch/data/`
- Пользовательские загрузки: `/DATA/AppData/ai-ch/uploads/`
- Обновлятор и его состояние: `/DATA/AppData/ai-ch-updater/`
- Конфигурация обновлятора и token GitHub: `/etc/ai-ch-updater.env` (права `600`, только на хосте; token не попадает в контейнер AI CH)
- systemd service: `/etc/systemd/system/ai-ch-updater.service`
- systemd timer: `/etc/systemd/system/ai-ch-updater.timer`

Обновлятор изменяет только `/app/app`, `/app/frontend` и `/app/requirements.txt` внутри существующего контейнера. База, загрузки и `.env` находятся отдельно и не должны удаляться при обновлении. Тем не менее перед важными обновлениями регулярно делай резервную копию каталогов `data/` и `uploads/`.

## Проверка состояния

```sh
systemctl status ai-ch-recovery.service --no-pager
systemctl status ai-ch-updater.timer --no-pager
systemctl list-timers ai-ch-updater.timer
docker inspect ai-ch --format 'running={{.State.Running}} restart={{.HostConfig.RestartPolicy.Name}}'
docker ps --filter name=ai-ch
docker logs --tail 100 ai-ch
```

Для переживания выключения или перезагрузки ZimaOS установщик задаёт контейнеру политику Docker `unless-stopped` и включает `ai-ch-recovery.service`. После запуска Docker служба дополнительно проверяет контейнер и запускает его, если он остановлен. База данных, загрузки и `.env` находятся вне слоя приложения и при таком восстановлении не удаляются.

Проверить журнал восстановления после загрузки:

```sh
sudo journalctl -u ai-ch-recovery.service -b --no-pager
```

Запустить проверку обновлений вручную:

```sh
sudo systemctl start ai-ch-updater.service
journalctl -u ai-ch-updater.service -n 100 --no-pager
```

Журнал обновлятора: `/DATA/AppData/ai-ch-updater/logs/updater.log`.

Отключить автоматические проверки:

```sh
sudo systemctl disable --now ai-ch-updater.timer
```

## Ограничения

1. Требуются root, Docker CLI, curl, tar, Python 3 и systemd на хосте ZimaOS.
2. Установщик не подключается к серверу удалённо: команды запускаются в терминале ZimaOS.
3. Код приложения копируется в записываемый слой контейнера без сборки образа. При обычном рестарте он сохраняется, но если ZimaOS удалит контейнер и создаст его заново из исходного образа, скопированный код может исчезнуть. Каталоги `data/` и `uploads/` смонтированы отдельно.
4. Первый старт устанавливает зависимости через pip внутри контейнера и может занять несколько минут; если он не проходит health-check, смотри `docker logs --tail 150 ai-ch`.
5. Health-check проверяет только доступность endpoint, а не работу всех AI-провайдеров, регистрацию, миграции или песочницу.
6. Автообновлятор копирует `app/`, `frontend/`, `requirements.txt` и отдельно обновляет runner из `sandbox/`; он не выполняет миграции базы автоматически. Runner получает собственный health-check и хранит код пользователя в отдельной рабочей папке.
7. Если контейнер с выбранным именем уже существует, установщик не удаляет и не пересоздаёт его. Он проверяет, что контейнер запущен и в нём есть `/app/app/main.py` и `/app/frontend/index.html`, после чего настраивает обновлятор.
8. Доступ к Docker эквивалентен широким правам на хост. Не открывай секреты и не добавляй `.env` в Git.
9. GitHub token хранится только в `/etc/ai-ch-updater.env` с правами `600`. Не помещай его в `/DATA/AppData/ai-ch/.env`, исходники, аргументы команд, сообщения или логи; при подозрении на утечку отзови token и создай новый.

## Файлы

- `install.sh` — установка AI CH с нуля и установка автообновлятора.
- `auto_deploy_daemon.py` — проверка GitHub, staged update, резервная копия, health-check и rollback.
- `ai-ch-updater.service`, `ai-ch-updater.timer` — systemd units.
- `.github/workflows/validate.yml` — синтаксические проверки.
