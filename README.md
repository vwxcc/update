# ai-ch Updater for ZimaOS

Автообновлятор для репозитория https://github.com/vwxcc/deepseekw. Установка рассчитана на **ZimaOS-хост**, где доступны **systemd** и Docker CLI, а само приложение **ai-ch** уже работает в существующем контейнере.

## Что делает

- Каждые 3 минуты получает SHA последнего коммита ветки **main** через GitHub API. При отсутствии изменений не скачивает исходники и не перезапускает приложение.
- Если появился новый SHA, загружает архив в отдельный каталог **releases/<sha>**.
- Проверяет обязательные файлы и синтаксис всех Python-файлов до переключения.
- Сохраняет резервные копии текущих **app/**, **frontend/** и **requirements.txt**.
- Перезапускает **существующий** контейнер, не собирая Docker-образ заново и не удаляя контейнер.
- Если изменился **requirements.txt**, устанавливает зависимости в отдельный каталог версии и переключает Python через файл **.pth**. Если зависимости не изменились, установка через pip не запускается.
- После запуска проверяет **HEALTH_URL** (по умолчанию **http://127.0.0.1:3050/api/health**). При ошибке пытается восстановить предыдущий код, выбор зависимостей и повторно проверить здоровье.
- Записывает состояние и журнал, а также блокирует параллельные запуски.

Обновлятор **не меняет** файл **.env**, переменные контейнера, базу, загрузки или другие данные. Он копирует только **app/**, **frontend/** и **requirements.txt**; стандартные каталоги данных **/app/data** и **/app/uploads** этим обновлением не затрагиваются.

## Установка на ZimaOS

Перед установкой убедись, что имя контейнера и порт приложения верны. Установщик проверяет, что выбранный контейнер существует и запущен.

В терминале **самого хоста ZimaOS** выполни:

    curl -fsSL https://raw.githubusercontent.com/vwxcc/update/main/install.sh -o /tmp/ai-ch-updater-install.sh
    sh /tmp/ai-ch-updater-install.sh

Запусти от **root**; если терминал не root, используй **sudo sh /tmp/ai-ch-updater-install.sh**.

Установщик спросит имя контейнера (значение по умолчанию — **chatstudio-v2**) и порт health-check (по умолчанию **3050**). Это только значения по умолчанию: подтверди их по реальной конфигурации ZimaOS. Если контейнер называется иначе, введи точное имя.

Установщик создаёт:

    /DATA/AppData/ai-ch-updater/
      auto_deploy_daemon.py
      state.json
      releases/
      backups/
      logs/updater.log
      updater.lock
    /etc/ai-ch-updater.env
    /etc/systemd/system/ai-ch-updater.service
    /etc/systemd/system/ai-ch-updater.timer

Он включает таймер. После загрузки хоста первая проверка запускается примерно через 2 минуты, последующие — каждые 3 минуты. **При первом успешном запуске обновлятор применяет текущую версию main, даже если файл состояния ещё не создан**, поэтому первый запуск может перезапустить приложение.

## Проверка и управление

Статус таймера:

    systemctl status ai-ch-updater.timer
    systemctl list-timers ai-ch-updater.timer

Запустить одну проверку немедленно:

    systemctl start ai-ch-updater.service
    journalctl -u ai-ch-updater.service -n 100 --no-pager

Журнал обновлятора: **/DATA/AppData/ai-ch-updater/logs/updater.log**.

В **/DATA/AppData/ai-ch-updater/state.json** сохраняются **remote_sha**, **applied_sha**, дата последней проверки, результат и SHA коммита, который не прошёл health-check. Если коммит уже не прошёл проверку, повторный автоматический перезапуск для того же SHA блокируется. Для повторной попытки после ручной диагностики останови сервис, удали из **state.json** поле **failed_sha** (или задай ему **null**), затем запусти проверку.

Отключить автопроверку:

    systemctl disable --now ai-ch-updater.timer

Проверить вручную после неудачного обновления можно также командой:

    python3 /DATA/AppData/ai-ch-updater/auto_deploy_daemon.py

## Настройки

Все параметры находятся в **/etc/ai-ch-updater.env**:

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| **GITHUB_REPO** | Репозиторий приложения | **vwxcc/deepseekw** |
| **GITHUB_BRANCH** | Ветка приложения | **main** |
| **TARGET_MODE** | Режим обновления | **docker** |
| **DOCKER_CONTAINER** | Имя существующего контейнера | ввод при установке |
| **APP_DIR** | Каталог кода внутри контейнера | **/app** |
| **HEALTH_URL** | Адрес проверки после рестарта | **http://127.0.0.1:3050/api/health** |
| **HEALTH_TIMEOUT** | Время ожидания после запуска, секунд | **90** |
| **KEEP_RELEASES** | Число сохраняемых релизов/резервных копий (минимум 2) | **3** |
| **UPDATE_ROOT** | Папка состояния, логов и резервных копий | **/DATA/AppData/ai-ch-updater** |

После редактирования файла можно сразу запустить **systemctl start ai-ch-updater.service**; перезапуск самого таймера не обязателен.

## Важные ограничения

1. Установщик не соединяется с ZimaOS удалённо и не меняет сервер автоматически. Его надо запустить на хосте, на котором есть доступ к контейнеру.
2. Обновлятор использует **docker cp**, а не пересоздание контейнера. Изменения сохраняются при обычном **docker restart**, но **если ZimaOS удалит и создаст контейнер заново из исходного образа, скопированный в слой контейнера код может исчезнуть**. Для такого сценария нужно отдельно настроить постоянный bind mount кода или другой способ развёртывания.
3. Docker-контейнер должен иметь каталог **/app/app**, **/app/frontend**, файл **/app/requirements.txt**, запускать приложение из **/app** и быть опубликован на порту, указанном в **HEALTH_URL**. Это соответствует структуре Dockerfile текущего **vwxcc/deepseekw**; кастомная конфигурация может отличаться.
4. Резервные копии кода хранятся в **backups/**, а загруженные версии — в **releases/**. Это не замена отдельной резервной копии базы данных и загруженных файлов.
5. Проверка HTTP health-check подтверждает только ответ endpoint, а не полноценное тестирование авторизации, AI-провайдеров, песочницы или миграций базы. Перед первым включением сделай отдельную резервную копию постоянных данных.
6. Если приложение завершится настолько быстро, что Docker не позволит выполнить команды внутри контейнера, восстановление кода через **docker cp** всё ещё возможно, но неиспользуемые старые файлы удалённого в Git каталога могут остаться внутри контейнера. Обновлятор не удаляет данные и не удаляет контейнер.
7. Доступ к Docker обычно даёт очень широкие права на хост. Храни **/etc/ai-ch-updater.env** с правами только для root и не добавляй секреты в Git.
8. Эта версия обновляет только веб-приложение (**app/**, **frontend/**, **requirements.txt**). Отдельный runner песочницы из **sandbox/** не изменяется: он использует отдельный образ и может быть запущен с read-only файловой системой. Для него нужен отдельный безопасный сценарий обновления.

## Файлы репозитория

- **auto_deploy_daemon.py** — одноразовая проверка/установка одного коммита.
- **install.sh** — установка таймера и конфигурации на ZimaOS.
- **ai-ch-updater.service**, **ai-ch-updater.timer** — unit-файлы systemd.

Обновлятор использует только стандартную библиотеку Python; дополнительных Python-пакетов устанавливать не требуется.
